# 双页码与正文起始页（2026-11-02）

用户要求整合现有跳转 UI，同时显示绝对页码与正文页码；支持任选一种跳转，正文前用罗马数字。

实现：
- 工具栏页码及跳转弹窗同时显示绝对页码、总页数与正文页码。
- 弹窗选择绝对／正文跳转。正文前从 i 顺序编号，大小写均可输入；非法、非标准罗马数字和越界输入不跳转。
- 输入正文起始绝对页码并设置，该页编号为 1；恢复自动清除手动覆盖。
- 自动模式在后台只读解析 PDF PageLabels，取首个正整数标签所在页面及其数值作为正文起点；没有标签或读取失败则从第一页的 1 开始。不做扫描页码 OCR，不支持附录前缀或多个独立重编号段。
- 手动覆盖写入 xnote manifest 的可选 body_start_page，缺失字段继续使用自动模式；不修改 PDF。设置接入原有脏标记及自动保存，保存失败沿用现有恢复流程。
- 起始位置按当前笔记的绝对页序保存，增删或重排页面后请检查起始位置。

API依据：[PDFBox PageLabels](https://pdfbox.apache.org/docs/2.0.10/javadocs/org/apache/pdfbox/pdmodel/common/PDPageLabels.html)。

目标真机验收待执行：标签PDF／无标签扫描PDF、设定起点、i/iv/正文/绝对跳转、无效输入、退出重开、恢复自动、横竖屏与侧边工具栏、软键盘、保存失败恢复。此次交互依据为用户需求；不宣称已验证 OneNote Android 对齐或 MovinkPad 兼容。

本机验证：JDK 21 下完整 testDebugUnitTest 与 assembleDebug 通过；新增页码逻辑测试与文档保存／重读／恢复自动测试通过。真机 UI、PDF 标签样本集与存储故障注入尚未执行。

追加交互：跳转弹窗新增“添加该页为起始页”，直接调用现有设置逻辑，将当前页面设为正文第 1 页并刷新输入值；保留手动输入和恢复自动。
