## Release 79 后续调查：退出分屏后的实时笔迹

用户报告 PDF 分屏后关闭新窗格、保留原 PDF，笔迹到抬笔才出现。对照已发布提交 `db3a5c01`，分页编辑器的实时前缓冲路径只失效外层 FrameLayout，绕过绘图 View 的 requestRender；分屏转换会重新挂接同一个绘图 View。此路径无法可靠保证子绘图视图重新记录并提交窗口帧，是本次优先修复的刷新风险，尚未在目标 GPU 上复现确认唯一根因。

修复统一失效绘图 View，由 vsync 合并重绘。已有前缓冲笔迹仍由 FrontInk 绘制，普通 overlay 会跳过它，避免双重绘制；保留 PDF/笔迹缓存，不增加文档同步或改写 PDF。可能增加前缓冲书写时的画布重绘开销，需真机观察实时显示与帧耗时。

按用户要求，本轮不打包 APK、不发布 Release。仅进行 Release 源码编译与 JVM 测试；不能据此宣称设备上的问题已消失。目标验收：PDF 打开后书写，分屏后书写，关闭新增窗格后持续书写（抬笔前可见），多次重复，并对比开启/关闭前缓冲和性能窗口帧耗时。

本轮验证结果：JDK 21 `:app:testReleaseUnitTest` 成功，2462 项测试通过，0 失败/错误/跳过；未执行 APK 构建或发布任务，未运行新增 Android/真机图层重挂验证。上述测试证明现有 JVM 回归未失败，不证明前缓冲显示问题已在设备上解决。
