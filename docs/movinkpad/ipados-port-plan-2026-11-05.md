# iPadOS 第一版移植计划（2026-11-05）

用户要求：参考 OwlLuna、Signotes、Saber 和 Linwood Butterfly，将当前项目移植到 iPadOS；第一版保留现有功能和 UI 实现，自定义快捷键暂不加入，改用已经确定的 Apple Pencil 系统事件，并将该方向设为项目目标。
状态：讨论完成并已形成实施计划；Xcode 27.2 可用，iOS 工程、源码实现、模拟器和真机验证均尚未开始。
本轮边界：只制定和记录计划；不创建 Xcode 工程，不打包、不安装、不推送、不创建远端分支，也不发布 TestFlight 或 App Store。

## 1. 目标与基线

iPadOS 第一版不是孤立的 PencilKit 演示，也不是删减功能后的新应用。它以制定本计划时的 Android `master`（`fb3ee329c63852cc9bdc5fce6fb194399ce364c7`）为行为基线，完成可日常使用的原生 iPad 版本，同时继续维护 Android 版本。

第一版的完成目标：

1. 保留分页笔记、PDF 批注、无限画布、图层、混排、双窗格、本地存储和 AI。
2. 保留当前黑白 UI 的信息架构、工具栏分类、焦点规则和浅色／夜间语义；适配 iPad 系统交互，但不借移植重新设计产品。
3. `.xnote` 继续作为两端共同的可编辑格式，不新建只能由 iPad 打开的主格式。
4. Android 创建的文档可在 iPad 编辑，iPad 保存后仍可回到 Android 编辑。
5. 原 PDF、迁移恢复资料、文档身份和图层归属不因跨平台而改变。
6. 使用 Apple Pencil 系统事件替代 Android 的 Pro Pen 3 和通用快捷键录入。

移植不改变下列既有边界：本地笔记不要求账号或同步；AI 只有用户主动发送后才联网；原 PDF 不被批注流程改写；尚未完成或尚待真机验证的 Android 能力不会因列入移植范围而被描述为已经验证。

## 2. 第一版范围

### 2.1 必须包含

- 文档首页、文件树、最近文档、创建、打开、重命名、移动、删除和回收站。
- 分页笔记、PDF 笔记和无限画布三种文档表面。
- 笔、荧光笔、橡皮、选择、套索、平移、撤销、重做及当前 Android 已支持的编辑工具。
- 手写、文本、图片、形状、连接线等现有混排对象及其保存恢复。
- 按页或按文档管理的 DrawingLayers，包括新建、命名、选择、显隐、锁定、删除、内容移动、直接拖动排序和单层缩略图。
- 单文档与应用内双窗格，保留首页替换、关闭、同文档双位置、焦点和共用工具栏规则。
- 内部引用式 `.xnote`、便携导出包、共享私有 PDF 对象、租约、延迟回收、旧包迁移和 SHA-256 重新关联。
- 英文与简体中文；浅色、夜间和用户内容颜色互不破坏。
- AI 多供应商、模型选择、思考深度、会话、草稿、附件、截图、PDF 工具、回收站和可选联网搜索。
- iPad 键盘、鼠标、触控板、横竖屏及 Scene 生命周期的基本适配。

### 2.2 第一版明确不包含

- Pro Pen 3 原始按钮位和 Android MotionEvent / KeyEvent 录入。
- 应用内自定义 Apple Pencil 快捷键映射。
- iCloud 同步、账号、多人协作或新的应用后端。
- 仅为 iPad 新增且 Android 尚不存在的 OCR、录音或识别功能。
- OneNote 原生文件格式兼容。
- 把 `.xnote` 替换为 `PKDrawing`、SwiftData 数据库或其他 iPad 专用主格式。

## 4. 固定 Apple Pencil 行为

第一版不提供快捷键配置页。Apple Pencil 事件先标准化为平台无关输入帧，再交给现有工具和文档语义。

| 输入 | 第一版行为 |
| --- | --- |
| 接触 / 移动 | 当前工具输入；采集精确位置、压力、倾角、方位和时间 |
| Coalesced touches | 作为正式高精度采样加入当前笔画，保持事件顺序 |
| Predicted touches | 仅绘制临时湿墨；真实点到达或结束时替换，不进入文档 |
| Estimated properties | 按 estimation update identity 修正对应点，不追加重复点 |
| 正常抬笔 | 提交当前笔画及延后的工具转换，形成一次明确撤销操作 |
| 系统取消 | 丢弃当前未提交笔画和该笔画内待提交转换，不冒充正常抬笔 |
| Hover | 显示当前工具、名义粗细和准确热点；离开、失焦或菜单覆盖时隐藏 |
| Double Tap | 遵循 iPadOS 的 Pencil 双击偏好：切橡皮、上一工具、显示面板或忽略 |
| Squeeze | 支持设备上显示笔尖附近的紧凑工具面板；不支持设备不显示入口 |
| Barrel Roll | 只改变有方向性的笔尖和荧光笔方向；圆笔等无方向工具忽略 |
| 手指 | 延续现有手指书写设置与导航、多指缩放规则，不与 Pencil 笔画串流 |

Apple Pencil 事件不映射为 Android 原始位，也不持久化临时设备 ID。能力检测决定界面是否出现，模拟器或不支持的 Pencil 不得伪造悬停、挤压或笔杆旋转结果。

## 5. 技术架构

### 5.1 仓库与模块

```text
app/                         Android 应用与平台实现
shared/
  core-model/               页面、对象、笔画、图层、文档身份
  core-geometry/            几何、命中、变换、网格化前算法
  core-history/             命令、撤销重做、选择语义
  core-tools/               工具状态、工具栏分类、平台无关输入帧
  document-format/          .xnote、画布、图层、模板、迁移
ios/
  XNotes.xcodeproj
  App/                      入口与依赖装配
  Domain/                   iPad 用例和共享核心适配
  Data/                     文件、设置、密钥、AI 历史
  Presentation/             SwiftUI 页面与 ViewModel
  Canvas/                   UIKit 输入、Metal 画布和文本宿主
  Platform/                 PDFKit、Document Picker、生命周期
  Tests/
compatibility-tests/        Android / iPad 黄金文件往返验证
```

共享层优先使用 Kotlin Multiplatform，避免重写约 3.2 万行核心逻辑和约 7800 行格式代码后产生长期分叉。`java.io.File`、ZIP、XML/JSON 流、线程和临时文件通过小接口隔离，由 Android 和 iPadOS 分别实现。

共享不是目的本身：Swift/Kotlin 高频边界以批次传递输入和几何快照。若真机证据表明 Kotlin/Native 热路径不能满足延迟或内存门槛，可将输入整形和网格生成移到 Swift，但格式和领域语义仍共享，不能未经证据整体复制两套核心。

### 5.2 UI 与输入

- SwiftUI 负责应用外壳、首页、侧栏、设置、菜单和对话框。
- UIKit `UIViewRepresentable` 承载高频画布、精确触摸、文本编辑宿主和与系统控件的交接。
- 现有 `Tokens.kt` 的语义映射到 iPad token，不在 SwiftUI 视图散落字号和间距字面量。
- 当前 48 dp 最小触控区在 iPad 保持不小于 48 pt；不为了平台迁移缩小已有命中范围。
- 工具栏仍按文档类型穷尽分类；未知工具不默认成为所有文档的共用工具。

### 5.3 绘制

PencilKit 用于能力验证和体验基准，不成为正式数据层。正式链路为：

```text
UITouch / UIEvent
  → PencilFrame 批次
  → 共享交互和工具状态
  → 预测湿墨快照
  → 正式 Stroke / CanvasItem
  → Metal 合成
  → .xnote 原子保存
```

Metal 至少区分纸面/PDF、已提交内容、实时湿墨、选择与光标标记。多层实时笔迹按正式层序合成；预测点和光标不进入导出、缩略图或撤销栈。工具标记继续使用与页面内容对比的反色描边，而不是机械跟随应用主题。

### 5.4 PDF 与文件

- PDF 首选 PDFKit，先用真实大型扫描 PDF 验证页面坐标、文字选择、缩略图、内存和并发行为。
- PDFKit 不满足既有语义或性能时，再评估 iOS PDFium；不能因方便而改变原件不可变规则。
- 外部文件使用 Document Picker / `UIDocument`、security-scoped URL 和 `NSFileCoordinator`。
- 私有不可变 PDF 对象放在 Application Support；显示缓存单独存放且可清理。
- AI 历史和附件放在排除系统备份的持久目录；API 密钥放 Keychain，不写入普通设置或导出。
- 所有导入、迁移和保存继续使用“临时写入→校验→原子发布”，失败时保留旧文件和恢复资料。

### 5.5 AI 生命周期

Swift 端使用 `URLSession` 实现现有 OpenAI Chat Completions 协议和 DeepSeek 工具请求。关闭 AI 界面、切换页面或新建会话不取消应用仍在前台的生成；显式停止或确认删除才取消。

iPadOS 进入后台后可能挂起进程，第一版不承诺无限后台生成。发送前和流式过程中持久化真实状态；进程重启后把未完成轮次标为中断，不冒充完成，不自动重发可能产生费用的请求。

## 6. 实施阶段与检查点

### P0：基线、参考审计和输入探针（1–2 周）

- 固定 Android 基线和功能/UI 对照表。
- 记录四个参考项目的提交、许可证和研究结论。
- 建立覆盖新旧 `.xnote`、PDF、画布、多图层、图片、文本、形状和失败恢复的黄金文件集。
- 创建最小 iPad 工程与 CI 骨架。
- 在模拟器验证应用结构，在至少一台 iPad + Apple Pencil 上记录接触、合并点、预测点、估计值、取消、悬停、双击和可用硬件能力。
- 用 PencilKit 建立系统体验基准，但不持久化为正式格式。

检查点 A：输入事件和设备矩阵有真机证据；共享边界、最低 iPadOS 版本和 PDF 技术探针结论明确。

### P1：共享核心和格式闭环（3–5 周）

- 抽取平台无关模型、几何、历史、工具语义和编解码。
- 保持 Android 测试和行为不变。
- iPad 读取黄金文件并生成结构化清单。
- 完成 Android 写→iPad 读/写→Android 重开往返。
- 对原 PDF、非 PDF ZIP 条目、文档身份、层 ID 和对象归属做逐项校验。

检查点 B：所有黄金文件双向可读；失败文件不覆盖原件；尚未支持的格式版本明确拒绝而非猜测读取。

### P2：iPad 应用外壳和本地文件（3–4 周）

- 首页、文件树、最近文档、回收站、设置和本地化。
- 黑白 token、夜间模式和选中反转。
- Document Picker、导入、分享、文件协调和原子保存。
- 私有 PDF 对象、索引、租约、延迟回收和重新关联。
- 应用内双窗格的容器、焦点和状态恢复骨架。

检查点 C：不依赖画布也能完成文件生命周期；强退、空间不足和损坏状态保留旧数据并给出明确提示。

### P3：Apple Pencil 与 Metal 编辑闭环（5–8 周）

- 原生输入适配、批次、预测点回收和取消语义。
- Metal 背景、正式内容、实时湿墨和标记层。
- 笔、荧光笔、橡皮、选择、套索、平移、撤销重做。
- 固定双击、挤压、悬停和笔杆旋转行为。
- 画布重挂、窗口失焦、菜单和多指手势交接。
- 抬笔保存、强退恢复和失败注入。

检查点 D：真实 iPad 上完成“创建→书写→擦除→撤销→保存→强退→恢复”；预测尾巴、取消残留和工具中途切换均无错误。

### P4：分页与 PDF（4–6 周）

- 分页布局、导航、缩放、插入空白和跨页对象。
- PDFKit 渲染、页面坐标、文字选择、缩略图和缓存。
- 原件/批注分离、引用式内部笔记和便携导出。
- 大型扫描 PDF 的可见页加载、任务取消和内存预算。
- 分页/PDF 的按页图层与单层缩略图。

检查点 E：混合页尺寸、旋转和裁切下笔迹不漂移；原 PDF 哈希不变；访问页数增长时内存和缓存保持有界。

### P5：无限画布、混排与图层（4–6 周）

- 无限视口、平移、缩放、可见区域裁剪和缓存。
- 当前已有的文本、图片、形状、连接线及其他混排对象。
- 图层侧栏、排序、重命名、显隐、锁定、删除和内容移动。
- 图层操作、橡皮碎片、跨页/跨层移动与撤销重做的身份保持。
- 黑白页面、彩色内容和工具标记的视觉规则。

检查点 F：Android 与 iPad 对同一文档的对象数、层序、边界、可见性和保存结果一致。

### P6：双窗格、工作区和完整 UI（3–4 周）

- 主菜单单文档打开、窗格内首页替换和显式分屏恢复。
- 同文件双位置、窗格关闭、物理位置保留和保存保护。
- 共用工具栏、文档栏、焦点高亮和独立文档设置。
- 横竖屏、键盘、鼠标、触控板和 iPad Scene 恢复。
- 与 Android 基线逐屏核对功能和信息结构。

检查点 G：快速打开、替换、关闭和恢复不会误关新文档或丢失后台保存；工具状态不因焦点显示规则而被修改。

### P7：AI（3–4 周）

- 多供应商、模型/深度、Keychain 密钥和模型获取。
- 会话任务、真实生成阶段、流式 String 类型检查和中断恢复。
- 草稿、附件、截图、PDF 工具和迟到回调隔离。
- 回收站、恢复、永久删除和保留天数。
- 可选联网搜索、工具不支持降级和失败反馈。

检查点 H：真实供应商另行授权测试；自动测试不打印密钥，不把删除会话复活，不因后台终止冒充生成完成。

### P8：兼容性、性能和交付候选（3–5 周）

- 全量黄金文件和 Android/iPad 往返。
- 单元、格式、输入回放、UI 和故障注入测试。
- 普通刷新率与 120 Hz iPad 的帧耗时和输入延迟。
- 大型 PDF、长时间书写、内存压力、低存储和进程重启。
- 英文/简体中文、浅色/夜间和横竖屏截图检查。
- TestFlight 候选构建、签名、安装和发布仅在用户另行授权后进行。

检查点 I：所有第一版完成标准有证据；未执行的设备、GPU、供应商或发布验证保留为待验证。

## 8. 验证矩阵

### 格式与数据

- Android 新建→iPad 打开；iPad 新建→Android 打开。
- 两端各编辑一次再回到起点，比较结构化清单而非只比较“能打开”。
- 默认单层继续沿用历史形式，多层才写入层元数据。
- 导入和迁移逐条保留未知、非 PDF 负载；不通过重绘或模型重编码“修复”旧笔迹。
- 原 PDF 和便携包内原 PDF 比较 SHA-256。
- 重复/缺失文档 ID、缺失私有 PDF、损坏索引和迁移中断均走显式恢复。

### 输入与绘制

- Pencil、手指、鼠标分流；手指取消不取消另一个输入身份的 Pencil 笔画。
- 合并点顺序、预测点替换、估计值更新和系统取消。
- 抬笔、失焦、Scene 切换、View 重挂和打开菜单。
- 双击、挤压、悬停和笔杆旋转分别按硬件能力测试。
- 多层实时笔迹、隐藏层预览、单层缩略图和选择标记对比。

### 文件与恢复

- 正常保存、抬笔后强退、临时文件发布前强退、磁盘不足和写权限丢失。
- Document Picker 的本机、iCloud Drive 和至少一个第三方 File Provider；使用 iCloud Drive 作为文件提供者测试不等于为应用增加同步功能。
- 分享/导出取消、失败和覆盖冲突。
- 私有 PDF 活跃租约期间不得被清理；缩略图和导出临时清理不得影响原件。

### UI 与工作区

- 笔记/PDF/画布的单独、两两和同文档双窗格组合。
- 焦点切换、后台工具状态、共用工具栏与独立文档设置。
- 英文/中文、浅色/夜间、横屏/竖屏、键盘出现/隐藏。
- 触控区、VoiceOver 标签、键盘焦点和外接键盘快捷键。

### 性能

- 60 Hz 与 120 Hz 分开记录，不用模拟器推断 Pencil 延迟。
- 当前帧、输入到显示、抬笔到提交、保存、首开和翻页分别测量。
- 大型扫描 PDF 使用真实页数、字节数、页面尺寸和哈希记录。
- 连续浏览和书写后内存、GPU 资源和缓存不随历史访问量单调增长。

## 9. 第一版完成标准

第一版只有同时满足以下条件才可标为完成：

1. Android 现有黄金文档可在 iPad 打开、编辑、保存并回到 Android。
2. iPad 新建的三种文档均可在 Android 编辑，不只是预览或导出 PDF。
3. 原 PDF 字节不变；引用式笔记、便携包和重新关联均符合既有身份规则。
4. 分页、PDF、无限画布都完成书写→保存→强退→恢复闭环。
5. 图层 ID 与对象归属在删除、排序、移动、橡皮碎片和撤销重做中保持一致。
6. 双窗格替换、关闭、失焦和恢复不丢数据，不误关新文档。
7. Apple Pencil 接触、取消、悬停、双击以及可用设备上的挤压/笔杆旋转行为有真机记录。
8. 黑白 UI、工具栏分类、焦点规则、英文和简体中文完成逐屏检查。
9. AI 密钥、历史和附件隔离；后台中断和删除后的迟到回调行为正确。
10. 未完成的设备、性能、供应商或发布验证明确写为待验证，不以源码检查替代。

## 10. 估算与风险

完整第一版预估 25–36 人周：单人约 7–10 个月，两名熟悉 iOS/图形的开发者合理并行时约 4–6 个月；约 8–12 周可得到包含真实 `.xnote`、Apple Pencil、分页/PDF 和恢复路径的首个内部真机版本。估算不包括 App Store 审核等待或新增产品需求。

主要风险按优先级排列：

1. Kotlin/Native 与 Swift/Metal 高频边界的延迟和内存。
2. 现有大型交互控制器从 MotionEvent 解耦时的行为回归。
3. PDFKit 对大型扫描 PDF、坐标、文字选择和缓存的实际表现。
4. Metal 湿墨、预测点回收、多层合成和 View/Scene 重挂。
5. Android/iPad 两端同时演进导致格式或工具语义漂移。
6. iPadOS 后台挂起与当前 AI 长任务语义的差异。

对应策略是先做输入/PDF/KMP 探针和黄金格式测试，再批量移植 UI；每个阶段保持 Android 可构建、可测试和可打开新旧文档，不以最后一次集中兼容修复承担全部风险。
